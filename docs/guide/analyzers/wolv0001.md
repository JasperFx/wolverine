# WOLV0001: Handler is not public

Wolverine only discovers public handler types and public handler methods. Anything else is skipped without a word,
and the first sign of it is usually a message with no handler.

This rule looks at the same types Wolverine's conventional discovery does: classes named `*Handler` or `*Consumer`,
`Saga` types, `IWolverineHandler` implementations and `[WolverineHandler]` classes. It reports:

* a class like that which isn't public, when it has a method that would be a handler
* a `Handle`, `Handles`, `Consume` or `Consumes` method (or the `Async` versions) on one of those classes that isn't public
* on a `Saga`, the saga method names too: `Start`, `Starts`, `StartOrHandle`, `StartsOrHandles`, `Orchestrate`, `Orchestrates` and `NotFound`
* any non-public method marked `[WolverineHandler]` on one of those classes

```csharp
// WOLV0001: the class is internal
internal class PlaceOrderHandler
{
    public void Handle(PlaceOrder command) { }
}

public class ShipOrderHandler
{
    // WOLV0001: the method is private
    private void Handle(ShipOrder command) { }
}
```

## How to fix it

Make the class or method public. If it isn't supposed to be a Wolverine handler, mark it `[WolverineIgnore]` or
give it a different name.

## What it leaves alone

The rule stays quiet about methods that only share a name with a handler:

* methods with no parameters, or whose first parameter is a primitive, a `string` or a `System` or `Microsoft` type
  like `Exception` or `CancellationToken`
* methods that return a primitive, generic methods, and overrides
* methods that implement an interface, so a MediatR, MassTransit or NServiceBus handler in the same application
  isn't reported
* types Wolverine would never discover anyway: abstract or open generic classes, `[WolverineIgnore]` types, and
  hand written `MessageHandler` subclasses
