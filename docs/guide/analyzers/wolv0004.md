# WOLV0004: IMessageBus resolved from IHost.Services in a test

`IMessageBus` is scoped. Resolving it from the root `IHost.Services` gives you a bus that isn't attached to a message
context, so tracked sessions, the outbox and context propagation don't behave the way they do inside a handler.

```csharp
// WOLV0004
var bus = host.Services.GetRequiredService<IMessageBus>();

// Do this instead. MessageBus() is an extension method in the Wolverine namespace
var bus = host.MessageBus();
```

The rule only runs in test projects, meaning projects that reference xUnit, NUnit, MSTest or TUnit, and it only
reports the direct `host.Services.GetRequiredService<IMessageBus>()` and `GetService` forms. Resolving the bus from
a scope you created yourself is fine.

## How to fix it

Use `host.MessageBus()`. See [Test Automation Support](/guide/testing).
