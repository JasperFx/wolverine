# WOLV0002: Saga identity member not found

`[SagaIdentityFrom]` tells Wolverine which public field or property of a message holds the saga identity:

```csharp
public class OrderSaga : Saga
{
    public string? Id { get; set; }

    // Fine: ShipOrder has an OrderId property
    public void Handle([SagaIdentityFrom(nameof(ShipOrder.OrderId))] ShipOrder command) { }

    // WOLV0002: ShipOrder has no OrderNumber member
    public void Handle([SagaIdentityFrom("OrderNumber")] CancelOrder command) { }
}
```

When the message type doesn't have a public member with that exact name (the match is case sensitive), Wolverine
quietly falls back to its other identity rules or to the `SagaId` envelope header, which usually isn't what you
meant.

## How to fix it

Use `nameof()` so the compiler checks the name for you, or fix the spelling.

## What it leaves alone

A saga message with no identity member at all is *not* reported. That's legal: Wolverine reads the saga identity
from the `SagaId` envelope header instead, which is how a saga's own timeout messages and the replies to messages
the saga sends find their way back. See [Saga Message Identity](/guide/durability/sagas#saga-message-identity).
